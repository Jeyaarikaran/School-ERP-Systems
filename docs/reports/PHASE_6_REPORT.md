# Phase 6 Report: Examinations, Marks, Results and Report Cards

## 1. What was built
- **Grading and Exam Setup:** Created schemas for `GradingSystem` (GPA or percentage_bands, with configurable Half-UP rounding) and `GradeBand`. Built `Exam`, `ExamClass`, `ExamSubject`, and `ExamComponent` mapping to handle complex structures (Theory/Practical/Internal) natively.
- **Invigilation Constraints:** Added `ExamSchedule` and `ExamInvigilation` schemas, protecting schedules from overlapping classes, rooms, or invigilators using PostgreSQL `EXCLUDE USING gist` constraints on `tstzrange(starts_at, ends_at)`.
- **Marks Entry and Workflow:** Created `MarkSheet` to track states (`not_started`, `draft`, `submitted`, `approved`, `reopened`) and version numbers (Optimistic Concurrency). Built `Mark` and an append-only `MarksHistory` table for rock-solid audit trails.
- **Calculation Engine:** Implemented a highly robust, pure-Python domain module (`app/domain/exams/engine.py`) using `Decimal` arithmetic exclusively. Handles:
  - Absolute mathematical consistency with HALF_UP rounding to two decimals.
  - GPA weighted aggregation.
  - Grade lookups mapping exactly to half-open interval boundaries.
  - Pure competition ranking (1, 2, 2, 4) handling unranked states (`withheld`, `incomplete`).
  - Safe extraction logic treating `absent` as zeros, and removing `exempt` elements entirely from totals/max.
- **Results and Report Cards:** Constructed `ExamSubjectResult`, `ExamResult`, `ReportPeriod`, `ReportCardRemark`, and `ReportCard` models tracking exact hashed payload state and PDF file linkage. Included the architecture required for Tamil language rendering (WeasyPrint/HarfBuzz) and external verification tokens.

## 4. ADRs Added & Deviations
- **ADR-026 (Pure Calculation Engine):** Separated all math into `MarksCalculationEngine` without any DB dependencies. This enables 100% test coverage using property-based testing (Hypothesis) for boundary cases and ties.
- **ADR-027 (Decimal Representation):** Enforced `Numeric` in PostgreSQL and `decimal.Decimal` in Python. Floating-point types are explicitly banned for marks processing to ensure percentage/GPA deterministic rendering.
- **ADR-028 (Append-Only Audit):** Adopted an insert-only `MarksHistory` table that records the original value, new value, reason, and initiator identity instead of triggering historical rows via generic database triggers, allowing the domain logic to specify context (`import` vs `entry` vs `correction`).
- **ADR-029 (Verification Link):** Each `ReportCard` has a unique random token permitting public verification queries mapping to secure hashes to prevent forgery.
